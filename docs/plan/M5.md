# M5 — Session policies and transport (exit criteria written before work started, 2026-10-11)

Goal (BRIEF §4.6 session policies, §7 M5; plan §7 layers 1, 2 and 4; decisions D5, D7): the session rules the user
decided, and a connection that friends can use without accounts. Order of work: session policies first (testable on
SINGLE-PC), then the connection layer, then a 4-player test package. Labels per test: SINGLE-PC / LAN / INTERNET, bots
or humans, impairment simulated or not.

## Exit criteria (all required)
| # | Criterion | Measurement / evidence |
|---|---|---|
| 1 | **Pause:** any of players 1-4 presses pause -> the game pauses on every instance at the same poll and every screen shows "Paused by Player N"; only that player or the host (player 1) can unpause; other players' unpause presses do nothing; the emulator-level pause (Esc) no longer stalls the other PCs silently (R-24) | 4 instances, scripted presses by each player in turn; screenshots of all four windows; lockstep 0 mismatches |
| 2 | **Cutscene skip:** during a skippable cutscene, presses by fewer than all connected players do not skip it and every screen shows "k/N want to skip"; when the last connected player presses, the cutscene ends on every instance at the same poll | 4 instances, scripted votes 1/4 .. 4/4; screenshots; 0 mismatches |
| 3 | **Disconnect:** when one player's connection drops, all other instances freeze at the same poll with "Waiting for Player N… 60 s" counting down; if the player comes back within 60 s with his game still running at the same point, play continues in sync | 4 instances, transport-level drop (simulated, no real network), reconnect at 20 s; 0 mismatches after resume |
| 4 | **Timeout choice:** after 60 s the host chooses (a) continue without that player - a taken-over companion returns to AI, a spawned Warrior is removed (D7) - or (b) restart from the last checkpoint without him; the remaining instances stay in sync in both cases | 4 instances -> 3; both choices tested; 0 mismatches for >= 5 min after the choice |
| 5 | **Host leaving** ends the session for everyone with a clear message; no instance hangs | 4 instances, host closed |
| 6 | **Joining only in the lobby:** a player who connects during a mission is not added to it and is told to wait for the next mission or checkpoint restart | 4 instances, late connect |
| 7 | **Saving:** co-op progress is kept on every PC separately from the player's single-player saves and never overwrites them; all instances start a session from identical co-op save data | memory-card files before/after; hash comparison at session start |
| 8 | **Connection:** the approved method (D5: direct with ICE + public STUN + join code) connects 2-4 instances: loopback test on SINGLE-PC, then LAN with the user's second PC, then INTERNET with the user's friends (needs the user's participation); direct IP entry still works on a LAN | session logs, connection success/failure per pair, RTT, stall time |
| 9 | **Originals unchanged** | `tools/hash_inputs.py` |

Out of scope for M5: all missions (M6), long soak and impairment hunting (M7), final packaging (M8).
Criteria 8 (LAN / INTERNET parts) need other PCs and people: they are prepared and handed to the user with exact steps.
