# M1 — Critical proof of concept (exit criteria written before work started, 2026-10-10)

Goal (plan §9): prove that two PCSX2 instances stay in sync through real story-mission combat using emulator-level
lockstep with input exchange, while each shows its own player's view full screen. Original 2-player mode only (no
4-player engine work). Stop and report to the user after M1 (decision D1).

## Components
1. **PCSX2 fork** at tag v2.9.115 (commit cf3c3720), built with MSVC (Build Tools 2026, F-0075). Upstream source in
   `emulator/pcsx2/` (separate git checkout, not committed here); our changes kept as a patch series in
   `emulator/patches/` plus build scripts. GPL-3.0.
2. **Fork features (W4P module):** session config (local slot, peers, input delay D, hash interval N); local input
   capture from the emulated pad (or a bot script); lockstep core over UDP behind a transport interface (loopback
   implementation for M1); frame gate at vsync that blocks while any player's input for the frames the game may read
   before the next vsync is missing; writes all players' inputs into the game's input ring in EE RAM at the gate;
   state hash every N game frames exchanged and compared; mismatch log with frame number and RAM dump; dynamic crop
   of the local player's view; OSD messages.
3. **Game patch (pnach, ours):** input ring injection at the libpad read (patch v2 mechanism, ring-indexed);
   layout forcing so each player's view has 4:3 proportions if needed.

## Exit criteria (all required)
| # | Criterion | Measurement / evidence |
|---|---|---|
| 1 | **Sync:** two instances, SINGLE-PC, loopback UDP, original 2-player mode, a story mission with combat, ≥ 10 minutes of gameplay, state hash every 30 game frames, **zero mismatches** | session logs with hash streams from both instances; bot input on both (seeded); label SINGLE-PC, bots, no impairment |
| 2 | **Impairment:** same as 1 with simulated 60 ms RTT and 10 ms jitter and 1 % loss inside the transport, ≥ 5 minutes, zero mismatches | session logs |
| 3 | **Presentation isolation (E2c):** instances show different views (P1 vs P2) and hashes stay equal; control run with no cropping also equal | logs + screenshots |
| 4 | **Views:** when the game renders separate views, instance A shows player 1's view and B shows player 2's view, each full screen with its own HUD; when the game merges to one view, both show the full frame | screenshots from both instances in both states |
| 5 | **Latency:** added input delay on loopback ≤ 2 game frames; average game frame rate ≥ 29 fps during gameplay; gate stall time reported | per-frame timing log |
| 6 | **Robustness:** no crash or softlock during the runs; a mismatch (forced by a deliberate one-frame input corruption in a test build) is detected and logged with frame number | logs |
| 7 | **Originals:** ISO, BIOS and original PCSX2 hashes unchanged | `tools/hash_inputs.py` comparison |

Human play is not required to pass M1 but a short human session on one instance (with a bot on the other) will be
offered to the user in the M1 report for feel and camera feedback.

## Out of scope for M1
Four players, the 4-player engine extension, internet/NAT traversal, lobby UI, session policies (pause owner, skip
vote, disconnect countdown), co-op saves.

## Result (2026-10-10)
All 7 criteria met on SINGLE-PC with bots; details and evidence in `docs/reports/M1_report.md`.
